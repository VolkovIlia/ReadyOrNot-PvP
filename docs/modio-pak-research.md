# PvP как `.pak` из меню «Моды» (mod.io): исследование

Вопрос: можно ли поставлять режим «SWAT против подозреваемых» как `.pak`, который игрок ставит из меню «Моды»
(mod.io) в главном меню игры, без RE-UE4SS и `RonCompNative.dll`.

Источники: JMAP-дамп рефлексии и бинарь игры (`re/dumps/`, локально), точечная декомпиляция в Ghidra
(`tools/ghidra_decompile.ps1`), поиск RIP-относительных ссылок и вызовов в `.text` и указателей UFunction в байткоде
Blueprint (скрипты сессии, в git не входят), [docs/re-findings.md](re-findings.md), публичные гайды по моддингу.
Адреса — статические VA при базе `0x140000000`, сборка exe от 07.10.2026.

## Коротко

- **Логику из pak игра запускает сама.** С версии 1.3 в игре есть `ModActorSpawnData` (MASD): data asset со
  списком акторов, которые игра спавнит на каждой загрузке карты. UE4SS для этого не нужен.
  - Спавн идёт **на каждой машине, где стоит pak**, без проверки роли в сети.
  - Если pak стоит только у хоста, логика работает только у хоста. Это та же схема, что у HostBrain сейчас.
- **Почти всё из Lua переносится в Blueprint.** Для этого нужен модуль-заглушка с объявлениями классов игры: через
  него Blueprint вызывает функции и пишет свойства, которые игра не открыла для Blueprint.
- **Нативные части в pak невозможны:**
  - патч правил «свой/чужой» — обход есть: не включать флаг скрытого PvP;
  - фильтр SWAT-RPC — обхода нет, есть только смягчения;
  - подавление очков — есть гипотеза, её нужно проверить.
- **Ставить pak должен только хост, но pak делает его игру «модифицированной».** Тогда у лобби атрибут
  `MODDED = true`. Ванильный клиент со штатными настройками такое лобби не видит в поиске, а при входе по
  приглашению получает «Cannot join a modded session». Помогает галочка «Подключаться к серверам с модами» у клиента
  или pak у него самого. Нынешний релиз на UE4SS хоста модифицированным не делает.
- **Рекомендация:** делать pak-версию «PvP Lite», но сначала короткая проверка осуществимости (этапы 0–1 ниже).
  Подробности — в конце документа.

## 1. Как игра загружает моды

Наблюдение:
- mod.io кладёт моды не в `Content/Paks/Modio`, а в `ReadyOrNot/Content/Paks/mod.io/3791/mods/<id мода>/`:
  - в `Saved/Logs/Modio.log` есть строка «Overriding RootLocalStoragePath to …\Content\Paks\mod.io\»;
  - шаблон пути в SDK — `{}/mods/{}`;
  - 3791 — id игры на mod.io.
  
  Сейчас в `cache/mods/*` у пользователя лежат только логотипы, установленных модов нет.
- Это подпапка `Content/Paks`, а движок при старте монтирует все `.pak` из неё рекурсивно. Так же работают
  ручные `~mods` и `LogicMods`.
- Нового мода нет в памяти до перезапуска: у `ModioManager` есть `IsRestartRequired`, у главного меню —
  `Initialize Mod Installing Modal`. Отключённые моды хранит `ReadyOrNotModData.DisabledMods` (SaveGame).
- Для логики модов игра даёт три нативных класса:

  | Класс | Что делает |
  |---|---|
  | `UModActorSpawnData : UDataAsset` | `TArray<TSubclassOf<AActor>> BlueprintsToSpawn` |
  | `UModPersistentObjectData : UDataAsset` | `TArray<TSubclassOf<UObject>> ClassesToInstantiate` |
  | `UModPersistentObjectSubsystem : UGameInstanceSubsystem` | BlueprintCallable static: `CreatePersistentObject`, `GetPersistentObject`, `GetAllPersistentObjects`, `RemovePersistentObject` |

  Ещё есть `ModLevelData` (свои карты в выборе миссий) и `ModCampaignData`.
- **Как работает MASD** (декомпиляция).
  - У `ModActorSpawnSubsystem` (`UWorldSubsystem`) переопределён слот vtable `+0x2d8`: `0x144e81c10`, у базы там
    пустая функция. Функция получает `UWorld&` и передаёт его в `SpawnActor`, поэтому это `OnWorldBeginPlay`.
  - Порядок работы:
    1. `AssetRegistry->GetAssetsByClass(ModActorSpawnData)`.
    2. Загружает каждый найденный ассет.
    3. Для каждого класса-наследника `AActor` из `BlueprintsToSpawn` вызывает `UWorld::SpawnActor` в начале
       координат со штатными параметрами.
  - Проверок `NetMode`/`HasAuthority` нет. `ShouldCreateSubsystem` не переопределён, так что подсистема есть в
    каждом игровом мире: в главном меню, в лобби и в миссии, на хосте и на клиентах.
  - `OnWorldBeginPlay` вызывается до `GameMode->StartPlay`. Значит, актор MASD появляется раньше старта миссии.
- `ModPersistentObjectSubsystem::Initialize` (`0x144e74d70`) так же собирает все `ModPersistentObjectData`.
  Объекты он создаёт через `NewObject` с владельцем-подсистемой (`0x144e62780`) и держит их в
  `PersistentModObjects`. Объект живёт весь сеанс игры и переживает `servertravel`.
- Публичные источники:
  - VOID ([Community Resources](https://voidinteractive.net/community-resources/)): MASD появился в 1.3 (Los
    Sueños Stories) и спавнит акторы на каждой смене уровня, включая главное меню. Нужен UE 5.3.2.
  - Сообщество сообщает: в **первом** главном меню после запуска игры MASD не срабатывает. Обход — зайти на любой
    уровень и вернуться.
  - Загрузчик Simple Blueprint Loader с Nexus из-за MASD стал не нужен.

Вывод:
- Точка входа для логики без UE4SS есть, и она официальная. Наш актор `BP_PvPDirector` в `BlueprintsToSpawn`
  работает так же, как сейчас тик HostBrain:
  - на хосте (`IsServer`) ведёт правила;
  - на клиенте с pak может рисовать UI;
  - без pak у клиента его просто нет.
- Состояние матча между перезагрузками миссии хранится в объекте `ModPersistentObject`; сейчас его держит Lua.

Неизвестно:
- Как игра заносит ассеты мода в AssetRegistry: читает ли `AssetRegistry.bin` из pak или сканирует путь. Отсюда и
  баг первого меню. Проверим на тестовом pak.
- Требуется ли `.sig` для мод-паков. Опыт сообщества говорит, что нет.

### Подмена ассетов игры

Наблюдение:
- Классика pak-модов: ассет по тому же пути в паке с суффиксом `_P` (приоритет патча) заменяет ассет игры.
  Для нового контента гайды, наоборот, советуют путь `Content/Mods/<автор>/` и имя без `_P`.
- `GM_COOP_{ActiveShooter,BarricadedSuspects,BombThreat,HostageRescue,Raid}_C` — пустые подклассы `GM_COOP_C`:
  0 функций, только значения по умолчанию. `GM_COOP_C` — тоже почти пустой наследник нативного `CoopGM`.
  `GS_COOP_*` устроены так же.
- `W_PreMission_C` — 111 функций, около 39 КБ байткода, 80 своих свойств. Исходного графа нет: из cooked-ассета
  граф не восстановить.

Вывод:
- **GameMode (`GM_COOP_*`) подменить можно.** Он есть только на сервере, так что хватит pak у хоста. Но придётся
  повторять значения по умолчанию из игры после каждого патча, а с MASD подмена не нужна вообще.
- **GameState (`GS_COOP_*`) подменять нельзя.** Он реплицируется, и разные версии класса у хоста и клиентов сломают
  репликацию.
- **`W_PreMission` подменять нереально.** Его пришлось бы собирать с нуля без исходников, и он клиентский, то есть
  нужен каждому игроку. Вместо подмены актор MASD кладёт свой виджет поверх экрана подготовки (`AddToViewport`) или
  в его панель.

### Что даёт «ModKit»

Наблюдение:
- Официального SDK у Ready or Not нет. В брифинге VOID от июня 2024 SDK обещан
  ([Vol. 74](https://voidinteractive.net/?p=1721)).
- Страница VOID [Community Resources](https://voidinteractive.net/community-resources/) отправляет к UE 5.3.2 и
  общественному **Community Mapping Framework** (Nexus, мод 1384). Это шаблонный проект `ReadyOrNot` с
  Blueprint-заготовками для карт и инструментом автоупаковки.
  - Сборка: cook под Windows → взять `Saved/Cooked/Windows/ReadyOrNot/Content` → упаковать UnrealPak
    ([гайд](https://unofficial-modding-guide.com/posts/mapping_gettingstartedue5/)).
  - Около 100 ГБ занимает распаковка ассетов игры через FModel. Нам она не нужна.
- Что именно лежит в CMF из C++ (заглушки модуля `ReadyOrNot`?) и откуда это взято, публично не описано.

Вывод:
- Для Blueprint-мода нужны UE 5.3.2 и проект с именем `ReadyOrNot`: тогда пути `/Game/...` и `/Script/ReadyOrNot`
  совпадут с игрой. Ещё нужен модуль-заглушка с объявлениями нужных нам классов игры.
- Заглушки генерируем сами из своего JMAP-дампа (рефлексия бинаря). Тогда не зависим от неясного происхождения CMF
  и не касаемся утёкших исходников. Хватит примерно 15 классов.

### Модуль-заглушка: почему без него не обойтись

Многие функции и свойства, которые трогает HostBrain, Blueprint по флагам не видит:

| Не `BlueprintCallable` | Свойства без записи из Blueprint |
|---|---|
| `ReadyOrNotPlayerController::ReadyUp`, `Server_SetReadyState` | `PlayerState.Team` (только чтение) |
| `ReadyOrNotPlayerState::OnRep_Team`, `Server_SetCustomization` | `ReadyOrNotCharacter.DefaultTeam` (protected) |
| `CoopGS::OnRep_CrouchingTigerHiddenDragon` (private) | `CoopGS.bCrouchingTigerHiddenDragon` (private) |
| `NotifyRespawnTime`, `Multicast_BroadcastChatMessage`, `Client_SendChatMessage` | `GameState.TimeTillGameStartCountdown`, `SWATManager.SquadLeader` (только чтение) |
| | `CoopGM.SuspectPlayerCustomizationOverride`, `CyberneticController.CombatActivity`, `bSpectateKillerOnDeath` |

- Флаги `BlueprintCallable` и `BlueprintReadWrite` проверяет только компилятор Blueprint в редакторе.
  - Cooked-байткод ссылается на `UFunction` и `FProperty` по пути импорта.
  - VM вызывает их напрямую: для RPC через `GetFunctionCallspace`, для остального через `Invoke`.
  - Поэтому заглушка с теми же именами и **точно теми же сигнатурами** (из JMAP), но с открытыми флагами даёт
    вызывать их из нашего Blueprint.
- Консольные переменные (`a.Ron…`) и `servertravel` доступны и без заглушки, через
  `KismetSystemLibrary::ExecuteConsoleCommand`. Это ровно тот вызов, которым пользуется Lua. Exec-функции
  контроллера (`DestroySwatTeam`) должны работать тем же путём (проверить), а если нет — через заглушку.

Проверить первым делом: что cooked Blueprint из нашего проекта действительно вызывает через заглушку
`ReadyUp` и пишет `PlayerState.Team` в живой игре.

## 2. Функции мода: что возможно в pak

«Заглушка» — нужен модуль-заглушка из раздела выше. Все действия выполняет актор MASD на хосте, если не сказано иное.

| Функция | В pak | Как |
|---|---|---|
| Выбор команд и меню на экране подготовки | **Да** | Свой UMG-виджет поверх `W_PreMission_C`. Класс найти через `LoadClassAsset_Blocking` по пути, экран — через `WidgetBlueprintLibrary::GetAllWidgetsOfClass`. Кнопки и события свои, хуки не нужны (в Lua они ломались при `RestartMod`). Команда: запись `Team` + `OnRep_Team` (заглушка). Готовность хоста: своя кнопка → `ReadyUp` (заглушка) или делегат `PC.OnPlayerReadyChange`. Удержание отсчёта — запись `TimeTillGameStartCountdown` (заглушка). Клиенты без pak выбирают команду в чате: `GameState.OnChatMessageReceived` (BlueprintAssignable, в `RChatMessage` есть `SenderPlayerState` и `Message`). У клиента с pak то же меню рисует его локальный актор, а выбор уходит хосту штатным RPC (чат или `Server_SetTeamType`). |
| Раунды с перезагрузкой миссии | **Да** | `ExecuteConsoleCommand("servertravel <карта>?game=<режим>")`, в одиночной игре — `open`. Карта — `GetCurrentLevelName`, режим — `GameModeBase.OptionsString`. Счёт, раунд и составы между загрузками хранит объект `ModPersistentObject`. Готовность клиентов — `Server_SetReadyState(true)` на сервере (заглушка). Итоги — свой виджет у хоста и чат (`SendChatMessage` BlueprintCallable, рассылка — заглушка). |
| Вселение в ИИ-подозреваемых | **Да** | `GetAllActorsOfClass`, `LineTraceSingle`, `K2_TeleportTo`, `K2_DestroyActor`, `ReadyOrNotGameMode::SpawnPlayerCharacter` (всё BlueprintCallable). Запись `DefaultTeam`, `Team` + `OnRep_Team`, `NotifyRespawnTime` — заглушка. Телепорт в первом кадре пешки — тик актора. Видимость для SWAT — `TargetingComponent::CanCharacterBeSeen` (BlueprintCallable). |
| Снаряжение и одежда подозреваемых | **Да** | `BpGameplayHelperLib::EquipLoadoutOnPlayer`, `InventoryComponent::DestroyInventoryItem`, `ReplenishAmmo`, `GetMagazineCount` — BlueprintCallable. Одежда: чтение `CoopGM.SuspectPlayerCustomizationOverride` и `Server_SetCustomization(…, true)` — заглушка. Подмена стволов (AK → SLR-47 и т. п.) — таблица в Blueprint. |
| Боты SWAT (`a.RonSpawnSwatInIncompatibleMode`, `hb_hunt.lua`) | **Да** (одно проверить) | Переменная без `ECVF_Cheat`, ставится через `ExecuteConsoleCommand`, как сейчас. `DestroySwatTeam` — Exec: через консоль (проверить) или заглушку. «Охотник»: запись `SWATManager.SquadLeader` (заглушка), `GiveMoveCommand` / `GiveSearchAndSecureCommand`, `CanCharacterBeSeen`, `ScriptedFireAtActor` (BlueprintCallable; чтение `CombatActivity` — заглушка). Выстрелы игроков вместо хука `Server_OnFire`: делегат `BaseMagazineWeapon.OnWeaponFire(Weapon, bServer)` (BlueprintAssignable) на оружии подозреваемых. Проверить, что на хосте он срабатывает для оружия клиентов. |
| Лимит лобби (`EOSMultiplayerStatics::SetMaxPlayers`) | **Частично** | Функция BlueprintCallable static, вызов прямой. Значение живёт в подсистеме GameInstance до выхода из игры. Но если MASD действительно не срабатывает в первом меню после запуска, первое лобби откроется на 5 мест. Лимит 10 будет со следующего лобби, после любого уровня. |
| Флаг `CoopGS.bCrouchingTigerHiddenDragon` | **Частично** | Запись и `OnRep_*` через заглушку возможны. Но без нативного патча (следующая строка) флаг делает гражданских врагами всех ИИ, и ИИ-отряд убивает заложников. **В pak-версии флаг не включаем.** Тогда враги считаются по обычным правилам: SWAT 1/2/5 против подозреваемых 3, гражданские нейтральны. Ровно это сейчас восстанавливает патч. Теряем три вещи: наблюдение и камеры только за своей командой, подавление радиоочереди, отключение автораспределения при входе (нам оно не мешает — команды мы ставим сами). Наблюдение частично чиним с хоста: возвращать камеру убитого на своего через `PC.Client_SetViewTargetWithBlend` (BlueprintCallable). |
| Native: правила «свой/чужой» (патч `IsEnemyTeam` / `IsFriendlyTeam`) | **Нет** | Это правка машинного кода. Обход — не включать флаг (строка выше). |
| Native: фильтр SWAT-RPC подозреваемых | **Нет** | Перехватить серверный RPC из Blueprint нельзя. Смягчения (проверить по одному): без наручников в наборе подозреваемый не арестует; `PlayerCharacter.YelloutEffectRadius = 0` у пешки подозреваемого на хосте (заглушка) — если сервер берёт радиус крика отсюда, крик ни на кого не действует; сброс `bHasBeenReported` после доклада. Запретить доклад в TOC, приказы гражданским и взаимодействие с персонажами нечем. `bDisableInteraction` закрыл бы и двери. |
| Native: подавление `Multicast_DisplayScore` | **Нет** (есть гипотеза) | Multicast из Blueprint не перехватить. Гипотеза: очистить на хосте `ScoringManager.ObjectiveScoreGroups` / `PenaltyScoreGroups` (Net, protected — заглушка), и начислять станет нечего. У клиентов с pak всплывающие очки можно прятать в их собственном HUD. |
| Native: защита `Multicast_StopSequence(nullptr)` | Не нужна | Нужна только нативным Firefight и Defusal (`comp_start`). В ко-оп PvP этого пути нет, в pak-версию эти режимы не входят. |
| Попутно: проверка попаданий (`HitRegistrationSettings.bEnableValidation`) | **Нет** (пока) | Это CDO или ini. У Blueprint нет записи в CDO, а замена `DefaultGame.ini` из pak хрупкая. Пока остаётся только в версии с UE4SS. |
| Попутно: консольные команды `comp_*` и `settings.txt` | **Да**, иначе | Консоли без UE4SS нет. Настройки — в меню, хранение — `SaveGameToSlot`. |

## 3. Кому нужен pak: хосту или всем

Наблюдение (декомпиляция):
- `ReadyOrNotGameInstance::IsGameModded` (exec `0x1448eb880`) возвращает глобальный байт `0x148e0daf0`. Его ставят:
  - монтирование pak мода (`0x144ea2060` заносит имя в список модов, `0x144e9c99b` — непустой список);
  - найденные файлы сложности `Difficulties/*.ini` (`0x144becda0`);
  - проверка в коде, который рядом читает `_worldgen_*.sav` своих карт (`0x144da341e`).

  UE4SS и DLL флаг не трогают. Нынешний хост с HostBrain — «немодифицированный».
- **Создание лобби** (`0x144ee465e`): атрибут сессии `MODDED = bAllowModdedPlayers || IsGameModded`.
  `bAllowModdedPlayers` — `GameUserSettings+0x371`, геттер `0x144de9c40`. При сохранении настроек
  (`0x144b94c90`) игра сама ставит `bAllowModdedPlayers = IsGameModded`.
- **Поиск лобби** (`0x144ee30aa`) фильтрует по `MODDED`:
  - ванильный клиент без галочки видит только лобби с `MODDED = false`;
  - модифицированный клиент — только лобби с `MODDED = true`;
  - с галочкой — все.
- **Вход в лобби** (`0x144ee7570`):
  - `MODDED = false`, а клиент модифицирован → «Cannot join session as mods are not allowed.»;
  - `MODDED = true`, а у клиента нет ни `bJoinModdedServers` (`+0x370`, `0x144deabd0`), ни своих модов →
    «Cannot join a modded session.»
- Значения в `GameUserSettings.ini` у пользователя: `bJoinModdedServers=False`, `bAllowModdedPlayers=False`,
  `bServerSideChecksum=True`. В меню «Настройки → Игра» есть переключатели `JoinModdedServers` и `AllowModdedPlayers`.
- **«Server Side Checksum» сейчас ни на что не влияет.**
  - Нативный геттер (`0x144deb950`) вызывает только Blueprint-обёртка `LoadServersideChecksum`.
  - Из Blueprint в дампе её зовёт только отладочный `W_PermanentOverlay`.
  - Строк о контрольной сумме pak в коде ReadyOrNot нет.
  - Оговорки: в дампе только Blueprint, загруженные при его снятии; прямое чтение поля нативным кодом не
    исключено. Старые жалобы на «pak checksum mismatch» в Steam относятся ко времени UE4.
- Механизма, который докачивал бы моды хоста клиенту при входе, в коде не нашли.

Вывод:

| Кто ставит pak | Что получается |
|---|---|
| Только хост | Правила работают: актор MASD есть только у хоста, всё остальное доходит до клиентов штатной репликацией, как сейчас. **Но каждому ванильному другу один раз нужно включить «Подключаться к серверам с модами»**, иначе лобби не видно, а приглашение даёт «Cannot join a modded session». Команду клиенты выбирают в чате. |
| Хост и клиенты | Галочка не нужна: клиент модифицирован сам. Его локальный актор (без авторитета) может показывать меню команд и прятать панель отряда SWAT у клиента-подозреваемого. Сейчас это ограничение из README. Версии pak у всех должны совпадать: актор не реплицируется, но меню клиента и правила хоста должны понимать друг друга. |
| Клиент с pak, хост без (нынешний UE4SS-хост) | Вход блокируется («mods are not allowed»), пока у хоста выключено `AllowModdedPlayers`. |

Актор MASD делаем нереплицируемым (`bReplicates = false`). Тогда клиенту без pak не нужно знать его класс, а
экземпляры на клиентах с pak живут сами по себе. Ветвление — по `IsServer` / `IsDedicatedServer` / `HasAuthority`.

## Проверка осуществимости без редактора (27.10.2026)

Редактора UE 5.3.2 на машине нет: Epic Games Launcher требует входа, а исходники движка этому GitHub-аккаунту
недоступны. Поэтому ассеты собираются напрямую, без редактора:
- **Компилятор `pakmod/kc`.** Пишет cooked-ассеты как JSON UAssetAPI: класс Blueprint, функции с байткодом Kismet,
  CDO и data asset. Дальше UAssetGUI 1.1.0 (`fromjson`) делает из JSON `.uasset`/`.uexp`, а `repak` упаковывает их в pak V11.
- **Размеры байткода.** В памяти UE 5.3 указатели занимают 8 байт, FScriptName — 12, смещения — 4. Правила проверены
  на 146 функциях четырёх Blueprint игры: совпали общие размеры, смещения `EX_Context` и цели переходов.
- **Нужен ли модуль-заглушка.** Нет: байткод ссылается на `UFunction` и свойства по пути импорта, а флаги
  `BlueprintCallable` и `BlueprintReadWrite` проверяет только редактор.

Наблюдение (тестовый pak `pakmod/targets/probe.py` в `Content/Paks/~mods`):
- Игра загрузила pak и создала актор из `ModActorSpawnData` **уже в первом главном меню** после запуска (сообщение
  сообщества о том, что в первом меню MASD не срабатывает, на этой сборке не подтвердилось) и снова в ко-оп миссии.
- `ReceiveBeginPlay` актора выполнился целиком. Шаги:
  - `GetPlayerController` (BlueprintCallable);
  - приведение `PlayerState` к `ReadyOrNotPlayerState`;
  - **запись `ReadyOrNotPlayerState.Team`** — свойство, которое Blueprint только читает: значение стало 4;
  - **вызов `ReadyOrNotPlayerController::ReadyUp`** — функция не BlueprintCallable: прошёл без ошибок.
- Таблица имён: имя вида `Ret_1` движок хранит как `Ret` с номером, поэтому в таблице должно быть и базовое имя.

Вывод: пункты 1 и 2 этапа 1 подтверждены на хосте, этапы 0 и 2 (редактор, заглушки, генератор графов) не нужны.
Логика пишется кодом и компилируется в байткод.

## Перенос режима (27.10.2026)

Вместо этапов 2–3 плана ниже (редактор, генератор графов) логика написана на подмножестве Python
(`pakmod/src/pvp.py`, около 1000 строк против 2400 строк Lua) и компилируется `pakmod/kc/lang.py`.
Классы:
- `BP_PvPDirector` — актор из `ModActorSpawnData`;
- `BP_PvPState` — объект `ModPersistentObjectSubsystem`: счёт и команды переживают перезагрузку миссии;
- `BP_PvPSave` / `BP_PvPLog` — сохранения настроек и журнала.

Проверено на хосте, одиночная игра на кампусе:
- меню команд на экране подготовки, удержание старта до «Готов»;
- кнопки (подписка на `W_StandardButton_C.OnClicked`), сохранение настроек в `RoNPvP.sav`;
- команда в чате `!suspect` через `ReadyOrNotGameState.OnChatMessageReceived` — сервер её ловит;
- старт раунда: хост-подозреваемый за 0,1 с занимает место ИИ, SLR-47 + G19, снято 10 SWAT-предметов, команда 3;
- отряд ботов начинает зачистку;
- конец раунда по времени: миссия загружается заново, раунд 2 стартует сам;
- смена сторон после раунда 2 (хост за SWAT, счёт переходит);
- конец матча (SWAT 3 : 0), «Новый матч»;
- pak подхватывается и из `Content/Paks/mod.io/3791/mods/<id>/`, как его кладёт меню «Моды»;
- если стоит и HostBrain (UE4SS), он уступает миссию директору pak-версии.

Не проверено (нужен друг): `servertravel` с клиентами, готовность клиента через `Server_SetReadyState`, вход
ванильного друга в «модифицированное» лобби.

## 4. Рекомендованный план

**Этап 0. Подготовка (2–3 дня, нужно согласие пользователя на установку UE 5.3.2, около 40–60 ГБ).**
- Проект UE 5.3.2 `ReadyOrNot`.
- Генератор модуля-заглушки `ReadyOrNot` из JMAP: только нужные классы, сигнатуры один в один.
- Скрипт cook → UnrealPak → копия в `Content/Paks/~mods` для проверки.

**Этап 1. Проверка осуществимости (2–3 дня и одна сессия с другом).** Тестовый pak с одним актором MASD:
1. Актор появляется на хосте в ко-оп миссии и в лобби, а в первом главном меню — да или нет.
2. Через заглушку работают `ReadyUp`, запись `PlayerState.Team` + `OnRep_Team`, `Server_SetCustomization`.
3. PvP без флага `bCrouchingTigerHiddenDragon`: урон между игроками, ИИ-подозреваемые союзны игроку-подозреваемому,
   гражданские живы, что видит наблюдатель.
4. Друг без pak входит после включения «Подключаться к серверам с модами»; `OnChatMessageReceived` на хосте ловит
   его `!suspect`.
5. Гипотезы: пустые группы очков не дают «+N»; `YelloutEffectRadius = 0` гасит крик; `OnWeaponFire` срабатывает на
   хосте для оружия клиента.

Критерий: пункты 1–4 прошли, значит pak-версию делаем. Не работает пункт 2 — без заглушек отпадают вселение, команды,
одежда и готовность, и pak-версия теряет смысл: остаёмся на установщике.

**Этап 2. Сборка Blueprint без GUI (1–2 недели).** Управление экраном пользователь не разрешил, а графы Blueprint
вручную в редакторе агенту не собрать. Нужен свой редакторный плагин или коммандлет: он собирает графы из текстового
описания (импорт узлов в текстовом формате копирования UE или прямое создание `K2Node`). Плюс в том, что исходник
логики остаётся текстом в git и его можно ревьюить.

**Этап 3. Перенос логики (3–4 недели).** Около 3 100 строк Lua (`hb_pvp`, `hb_menu`, `hb_loadout`, `hb_hunt`,
`hb_common`, `main`; `hb_solo` не нужен, его заменяет меню PvP) переходят в `BP_PvPDirector`, виджет меню и объект
состояния матча. Порядок: меню и команды → раунды → вселение и снаряжение → боты → лимит лобби.

**Этап 4. Публикация (около недели).** Чек-лист с другом ([pvp-playtest.md](pvp-playtest.md)), страница на mod.io с
инструкцией про галочку «Подключаться к серверам с модами». Публикация — с согласия пользователя.

Итого около 6–9 недель до pak-версии без нативных частей. Основные риски:
- нет официального SDK;
- первое меню без MASD;
- обновления игры, которые меняют сигнатуры, — тогда пересобирать заглушки.

## Рекомендация

**Делать pak-версию — да, но только после этапов 0–1.** Состав:

- **Входит («PvP Lite», ставит только хост):**
  - меню команд поверх экрана подготовки;
  - выбор команды клиентами через чат;
  - раунды с перезагрузкой миссии и сменой сторон;
  - вселение в ИИ-подозреваемых;
  - оружие и одежда подозреваемых;
  - боты SWAT и «охотник»;
  - лимит лобби 10 (с оговоркой про первое лобби).
- **Меняется:** флаг скрытого PvP не включаем. Гражданские нейтральны по штатным правилам; наблюдение за своей
  командой чиним с хоста частично.
- **Не входит:**
  - фильтр SWAT-RPC — только смягчения: нет наручников, крик без эффекта;
  - подавление очков — если гипотеза не подтвердится;
  - проверка попаданий;
  - нативные Firefight и Defusal.
- **Цена для игроков:** каждому другу нужно один раз включить «Подключаться к серверам с модами» или поставить pak
  самому. С pak у клиента у него будет и своё меню команд.

Нынешний установщик на UE4SS остаётся как вариант со строгими правилами. Когда pak-версия заработает, стоит сократить
UE4SS-часть до надстройки над pak: только нативные защиты из `RonCompNative`, а вся логика — в Blueprint. Тогда
кодовая база останется одна.
